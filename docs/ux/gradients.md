# Tonal gradient review — 2026-10-30

This is the third approved UI brief, following the flat presentation/usability
checkpoint `f1ed3f9`. It permits new palette-derived backgrounds, not palette
changes. The original 976 color entries remain intact. No dependencies, images,
network assets, application state or control geometry were added.

## Inventory and support

The five legacy gradient rules in `styles.css` target body, empty-chat icon,
Knowledge setup, onboarding and login. Existing workspace rules override them;
they are preserved for the earlier color freeze. Existing shadows use `--shadow`,
and overlays use `--scrim`; no new glow, shadow or blur is introduced.

The desktop manifest requests Electron `^43.2.0`; the lockfile pins **43.7.9**,
whose [release record](https://releases.electronjs.org/release/v43.7.9) specifies
Chromium **150.0.7871.250**. Test Chromium is **151.0.7922.34**. Vite targets
`es2022`, which is a JavaScript target, not a CSS compatibility guarantee.
[Chrome's color documentation](https://developer.chrome.com/docs/css-ui/css-color-mix)
documents Oklab mixing and interpolation. Production rules are gated by actual
`@supports` checks for both operations; unsupported browsers retain flat fills.
No `@property`, masks, scroll timelines or `@starting-style` are required.
The current workspace has no local Electron executable for a fresh installed
window capture; desktop unit/syntax checks do not replace that check.

## Retained treatments and budget

Light originates at the top. Dark raised surfaces brighten toward the top;
light surfaces shade toward the bottom. Three decorative treatment families are
allowed per screen, not three effects on every element. There is no canvas glow.

| Token | Purpose / consumer | Dark stops | Light stops | Flat fallback |
| --- | --- | --- | --- | --- |
| `--gradient-sidebar` | Quiet shell depth / sidebar | surface-1 at 0%, surface-0 at 70% | surface-1 at 0%, surface-0 at 100% | Existing surface-0 |
| `--gradient-composer` | Lift input area / Chat composer | surface-2 at 0%, surface-1 at 55% | surface-1 at 0%, 60% surface-1 + 40% surface-2 at 100% | Existing surface-1 |
| `--gradient-primary` | Distinguish primary action / primary and final Send–Stop buttons | text at top, 92% text + 8% surface-3 at bottom | 90% text + 10% surface-3 at top, text at bottom | Existing primary fill |
| `--gradient-progress` | Functional transfer fill / downloading or finalizing bar | text weight eases 100% → 88% against surface-3 | text weight eases 100% → 82% against surface-3 | Existing text fill |

Every ramp uses Oklab. Progress has nine stops sampled from smoothstep
`x²(3−2x)`, generated by `scripts/maintenance/generate-ui-gradients.mjs` into
`tokens.css`. It is a static eased tonal fill, not a fake indication of speed.
Nothing fades to transparent and no alpha/noise tile is needed.

Chat uses sidebar + composer + primary controls. Agents/Models use sidebar +
primary controls; Settings/Knowledge/Activity use at most those two. Progress is
functional and sits behind no text. New gradients are entirely static. Existing
press/entrance transforms retain reduced-motion behavior.

Set `data-gradients="off"` on the root HTML element to flatten **all four**
tokens centrally. Forced colors and increased contrast do the same. This is a
presentation diagnostic switch, not another saved user preference or a new
setting. Browser behavior, underlying colors and geometry remain unchanged.

## Prototypes, rejection and limitations

Four isolated desktop prototype cases (both themes and English/Arabic) produced
56 images before production consumers were wired. Direct review included Chat,
Agents and Models. The first prototype selector was narrowed so the microphone
remains a flat secondary action. On/off comparisons then cover all retained
treatments at 390/1440px, both themes, English and Arabic.

- Ambient canvas glow: rejected; it weakens separation from reading content.
- Card/nav/selected/overlay gradients: rejected; existing fills already signal
  state and additional treatments exceed the hierarchy budget.
- Gradient borders and top highlight overlays: rejected for this pass; preserve
  the existing outline/focus grammar rather than adding weak duplicate borders.
- Transcript/history scroll scrims: deferred; a static fade would falsely imply
  more content at a fully scrolled edge. No scroll-state JS was added for decoration.
- Animated sheen/skeleton gradients: rejected; no demonstrated benefit over the
  existing restrained loading indicators on low-power devices.
- Desktop startup: deliberately flat, matching its existing theme palette.
- Dither: not added. No obvious banding was seen in representative PNG review;
  physical 8-bit displays and boosted-contrast inspection are not qualified.

## Contrast

The browser samples 101 Oklab mixtures across each surface envelope and the full
primary/progress endpoint range. The composer bound is deliberately more extreme
than the actual light-mode ramp. Ratios below are conservative minima.

| Pair | Light | Dark |
| --- | ---: | ---: |
| Sidebar / text | 16.72 | 16.26 |
| Sidebar / muted | 7.19 | 9.03 |
| Sidebar / faint | 5.13 | 6.14 |
| Composer / text | 15.57 | 14.57 |
| Composer / muted | 6.70 | 8.09 |
| Composer / faint | 4.78 | 5.50 |
| Primary / on-accent text | 12.08 | 11.98 |
| Progress / track | 9.32 | 8.37 |

All new text-over-gradient pairings exceed 4.5:1. Progress/track and primary fill
boundaries are tested against 3:1. Existing faint hairline separators are not
claimed to meet a blanket 3:1 boundary target; they were not recolored. Answers,
code, secondary fields/buttons and semantic error states remain flat.

The palette check allows only the explicitly named generated additions and
reviewed consumers; it cannot authorize removal or alteration of a baseline
color entry. The generator check independently detects drift in the token block.
Regular tests cover computed gradient presence, unchanged geometry, off mode,
forced colors, increased contrast, reduced motion, live progress and RTL.

Evidence lives under `build/ui-craft`: `before`, `after`, `gradient-prototype`,
`gradients`, palette proofs and the paint report. These are synthetic local test
artifacts, not user data or installed-platform qualification.

The separate 4x/6x stress fixture traces real renderer Paint events while a long
answer streams and while transfer progress polls. It retains the 250 ms Stop
assertion and records failures honestly. The first run exceeded that target
with gradients **off** (361.8 ms), showing a gradient-independent heavy-stream
limitation in this candidate. It does not establish when that limitation began.

Low-power long-stream qualification remains open. A separate follow-up should
profile Markdown rerendering and input scheduling, with the same Stop gate and
without changing task cancellation semantics. This presentation pass does not
claim that follow-up is implemented.
