# Tasks

These tasks implement M2.02 without replacing the roadmap. None is complete from planning. Network-dependent production dispatch remains unavailable until task 1.1 has established the required boundary. A failing feasibility result is useful evidence, not completion of attachment support. All fixture paths, origins, subprocesses and profiles must be isolated; real registration, installed profiles, publication and accounts remain separately authorized gates.

## 1. Resolve enforcement and protocol before admission

- [ ] 1.1 Build disposable-browser network feasibility probes for exact tab rules, redirects/subresources, private/rebinding destinations, same/OOPIF frames, workers/cache, popups, and pre-existing/new WebSocket/WebTransport/WebRTC activity. Require independent destination/effect counters and an unrelated sentinel tab; record exact versions, commands and prevention failures in the research evidence. Keep dependent automation disabled and obtain design review if the required boundary cannot be met without modifying the user's profile. Verify probes with a focused `node --test` suite and retain both failing counterexamples and positive controls.
- [ ] 1.2 Finalize a versioned attachment wire contract and threat model in design/API documentation: exact actor/workspace/run/input/policy/resource binding; managed default; extension/host/service compatibility; bounded framing/chunks/queues; Stop/revocation; native peer identity; borrowed/created ownership. Review the actual Chrome/Edge API and package constraints against the source matrix, and add executable schema/negative-fixture checks before enabling admission. No static ID or extension installation alone may authorize a task.

## 2. Implement the local transport and explicit selection

- [ ] 2.1 Add the minimal packaged MV3 selection/Stop surface and strict native-message protocol adapter. Test browser-owned selection, untrusted page messages, forged IDs, unsupported versions, oversize/truncated frames, duplicate/conflicting sequences, backpressure, worker restart and EOF. Use actual extension execution in disposable state where available and a real framing subprocess; record any mocked boundary separately. Document manifest permissions and why no global tab/profile inventory is needed.
- [ ] 2.2 Implement user-restricted native-host-to-desktop ownership and fresh task-scoped consent, retaining maintenance admission holds and current authenticated principal checks. Add focused desktop tests for wrong peers, another actor/workspace, changed consent, host replacement, lost reply and local Stop while offline. Verify with `npm --prefix apps/desktop test` and update computer-access documentation with explicit installed-host limitations.
